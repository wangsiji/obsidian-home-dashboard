# 0.3 development: module library and direct layout editing

Development build only. No 0.3 tag, release, official scan or marketplace update has been performed.

## User flow

1. Open Home → **Add content** to browse local module previews, search titles and sources, and add a module to the current page.
2. Create a page with **+**. The module library opens directly after naming it.
3. Use each card's **…** for item count (1–6, default 3), move to another page, ordering or removal.
4. Use page **…** to rename, copy, reorder or delete a page. Deleting a page requires confirmation and never deletes source notes.
5. **Edit layout** exposes drag handles. Menu ordering is also available for keyboard use.

The library opens the normal Obsidian installation/settings screen for absent or disabled dependencies. It does not install or enable plugins automatically. A loaded source without an available Home provider is shown as unavailable rather than incorrectly requesting an update.

## Compatibility

- Existing pages and plugin-level limits/visibility remain valid.
- Section identities encode both provider and section ID. Explicit section settings take precedence over inherited provider settings.
- Copied pages own independent options and ordering; moving refuses to overwrite a module already visible in the destination.
- Saved writes are serialized to prevent rapid additions from persisting an older settings snapshot.
- Saved third-party source IDs remain discoverable when their plugin disappears. Unavailable configured sections remain removable.

## Custom shortcut groups

- Library → Shortcuts → Add. Pick a vault file/folder or enter a full http/https URL. Optional names fall back to the current filename/domain, with 16 built-in icon choices.
- Groups are page-local, support copy/move/hide/restore, and use the existing module ordering. Their entries have independent drag ordering, earlier/later menu actions, edit/remove and move-to-group actions.
- URLs are only opened on an explicit click. No favicon service, website scraping or background website request is used.
- Vault rename events update folder and descendant file targets across pages. Missing targets remain editable; removing an entry does not delete the source.
- Folder navigation uses guarded native file-explorer capabilities, tested for both reveal and expansion in Obsidian 1.13.7.

## Simple Todo and customization entry

- Idle toolbar shows only a settings icon labelled Customize Home. Editing reveals labelled Add content and Done actions.
- Todo is opt-in from the library, default three pending tasks, with the existing 1–6 display limit. First submission creates Home Todo.md; the source label opens a picker for an existing Markdown note. All pages share that task note; visibility and count remain page-specific.
- Standard Markdown is the sole task store. Completion changes only the checkbox, rejects stale snapshots, skips YAML/fenced examples/custom statuses, and preserves duplicate text, CRLF and child lines. Open editors use minimal replaceRange; closed files use Vault.process.
- Vault modifications and editor changes refresh task lists; rename updates the chosen path. Input drafts survive normal rerenders. A missing chosen file produces a save error instead of recreating it.
- No Tasks adapter or automatic daily-note rollover. Unfinished tasks persist in the chosen fixed note across days.
- 46 tests pass; zero lint errors, six existing warnings. Isolated Obsidian testing exercised gear/edit toolbar, form submission, completion and backing Markdown reads. A user-added task appeared during QA, so that entry was preserved in Home Todo.md while generated QA rows were removed; rename and plugin-reload persistence were verified. Mobile remains unverified.

## Daily Todo and carry forward

- Daily notes are now the default write destination, respecting existing folder, format and template. Fixed-note mode remains available; daily-disabled mode falls back to the selected task note. Old fixed-note content is not migrated without a carry action.
- Add under 今日待办; display today's tasks first. Earlier dated notes and the selected legacy fixed note provide carry candidates. Full and selected carry actions move parent tasks with indented descendants into 昨日未完成 and leave dated source links.
- Automatic carry is opt-in, off by default. Writes check snapshots, serialize carries and keep a recovery journal across the two file writes. Target is written before source replacement. Conflicting edits stop recovery rather than overwrite them; retry resumes a pending journal without inserting another target copy.
- 54 tests pass, including nested tasks, selection, duplicate task text, heading placement, source-write failure, idempotent recovery and conflict preservation. Real isolated Obsidian checks covered selective/full/automatic carry, source links, nested tasks and new daily insertion. Temporary daily settings were restored and generated fixtures trashed; user's fixed-note task remains intact. Final build stays in the isolated test vault only. Mobile is unverified.
